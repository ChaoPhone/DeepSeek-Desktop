# UX 交互逻辑分析

## 分析框架：用户想要 → 用户做了 → 发生了什么 → 问题点

---

### 场景 1：快速打开某个 AI

| 维度 | 内容 |
|------|------|
| 用户想要 | 快速访问某个常用 AI |
| 用户做了 | hover 主球 → 等待 200ms → 副球展开 → 识别副球 → 点击 |
| 发生了什么 | 副球扇形展开（上、左上、左方向），点击后打开对应 AI 窗口 |
| 问题点 | 1. 副球标签太简短（DS、GPT、GE、GLM），新用户难以识别<br>2. 副球展开方向固定左上，屏幕左侧悬浮球展开后可能超出边界<br>3. 200ms 展开延迟 + 300ms 收缩延迟，交互节奏感不够流畅<br>4. hover 意外触发：鼠标路过即展开，可能挡住其他内容 |

---

### 场景 2：切换默认 AI

| 维度 | 内容 |
|------|------|
| 用户想要 | 把某个 AI 设为默认（单击主球打开的那个） |
| 用户做了 | 右键主球 → 点击菜单中的 AI 名称（带 ✓ 标记） |
| 发生了什么 | 切换成功，主球图标变为该 AI 图标，菜单关闭后刷新悬浮球 |
| 问题点 | 1. 切换后视觉反馈不够明显，用户可能没注意到主球图标已变<br>2. 菜单关闭时 refreshBallWindow 可能导致短暂闪烁 |

---

### 场景 3：调整悬浮球大小

| 维度 | 内容 |
|------|------|
| 用户想要 | 调整悬浮球视觉大小（更大或更小） |
| 用户做了 | 右键 → 自定义外观 → 拖动大小滑块 |
| 发生了什么 | 悬浮球 CSS 大小实时变化，窗口位置固定不变 |
| 问题点 | 1. 设置窗口是模态子窗口，用户调整时看不到悬浮球实际效果<br>2. 没有预览功能，用户需要反复调整确认<br>3. ✓ 已修复：窗口位置不再偏移 |

---

### 场景 4：临时隐藏悬浮球

| 维度 | 内容 |
|------|------|
| 用户想要 | 悬浮球挡住某个区域，想临时隐藏 |
| 用户做了 | 尝试右键菜单... **没有隐藏选项** |
| 发生了什么 | 用户只能拖动悬浮球到屏幕边缘或其他位置 |
| 问题点 | 1. 缺少临时隐藏功能<br>2. 用户可能希望双击主球隐藏，或右键菜单有"隐藏悬浮球"选项 |

---

### 场景 5：同时使用多个 AI

| 维度 | 内容 |
|------|------|
| 用户想要 | 对比多个 AI 的回答 |
| 用户做了 | 点击不同副球打开多个窗口 |
| 发生了什么 | 多个独立窗口，各有品牌色刘海，任务栏分开显示 |
| 问题点 | 1. 窗口标题被网页 title 覆盖，难以区分是哪个 AI<br>2. 刘海颜色区分度不够高（GLM 灰色与普通灰色接近） |

---

### 场景 6：意外触发副球展开

| 维度 | 内容 |
|------|------|
| 用户想要 | 鼠标路过悬浮球区域，**不想**触发任何操作 |
| 用户做了 | 鼠标划过主球（无意图） |
| 发生了什么 | 200ms 后副球展开，可能挡住用户想点击的其他内容 |
| 问题点 | 1. hover 触发过于敏感，无意图操作也会展开<br>2. 收缩需要等待 300ms，用户移开鼠标后副球仍短暂停留 |

---

## 交互优化建议

### 优先级 P0（核心体验）

1. **副球展开方向自适应**
   - 根据悬浮球位置智能选择展开方向
   - 屏幕左侧 → 向右展开
   - 屏幕右侧 → 向左展开（当前）
   - 屏幕顶部 → 向下展开
   - 屏幕底部 → 向上展开

2. **临时隐藏悬浮球**
   - 右键菜单添加"隐藏悬浮球"选项
   - 隐藏后在任务栏显示托盘图标，点击恢复
   - 或：双击主球隐藏/恢复

### 优先级 P1（体验提升）

3. **副球标签优化**
   - 改为完整名称：DeepSeek、ChatGPT、Gemini、GLM
   - 或：tooltip 提示完整名称

4. **设置窗口改为非模态**
   - 用户可同时看到悬浮球效果
   - 或：设置窗口内添加实时预览区域

### 优先级 P2（细节优化）

5. **切换默认 AI 的视觉反馈**
   - 切换后主球短暂放大 + 边框颜色变化
   - 提示用户"已切换为 DeepSeek"

6. **hover 触发阈值调整**
   - 增加 hover 时间阈值（如 500ms）减少意外触发
   - 或：需要轻微移动才触发展开（静止 hover 不展开）
